# 複数回の訂正と確認対話

作業前チェックポイント `af622f5`。既存のタスク列と歩行制御を使い、複数回の入力と確認応答を追加した。
依存関係・制御方策・物体配置は変更していない。

## 仕組みと入力

訂正JSONに `question` と `status=clarify` を追加した。
曖昧な場合は既存のタスク列を変更せず質問し、ロボットはゼロ速度の下で物理・姿勢制御・観測を続ける。
次の入力には会話履歴と最新の状態を渡すため、「緑です」のような回答も解釈できる。
`accept` で検証を通った後に再開する。未対応要求の `reject` と不正出力・モデル失敗は従来どおり失敗として停止する。

元の締切と帰還条件を保持し、質問の待ち時間も同じ予算へ含める。
回答がない場合は帰還余裕を残して `not_found` として帰還し、未達成タスクをログに残す。
LLM待ちの途中で締切そのものが尽きた場合は失敗として停止する。待ち時間中の帰還完了を無条件に保証するものではない。

1回の任務で最大12メッセージ、各500文字、タスク列は最大8件。帰還開始後の訂正は受け付けない。
完了・取消し済みIDの再利用を禁止し、まだ実行中の再確認が参照する観測も次の入力へ残す。
取消しの引用は人の入力から検証するが、その文の意味解釈が常に正しいことまでは保証しない。

ライブ入力は `--correction-file` でUTF-8の文を置き換える。初回と同じテキストは再読み込みしない。
同じ文を意図的に繰り返す場合は、`{"id":"turn-3","message":"緑をもう一度確認して"}` のように異なるIDを付ける。
同じIDは1回だけ受け付ける。複数入力を処理中にファイルを何度も上書きすると途中の入力を失うので、回答を待って次を送る。
書き途中のJSONを避けるため別ファイルから原子的に置き換える。

再現用には時刻順のJSON配列を `--correction-script` で渡す。最大12件・16 KiB。

```bash
bash scripts/demo.sh --task search --planner codex --seed 305 --correction-script examples/dialogue-short-answer.json --headless
bash scripts/demo.sh --task search --planner codex --seed 305 --correction-script examples/two-corrections.json --headless
bash scripts/demo.sh --task search --planner codex --seed 0 --prompt '青を探して帰還して。全体60秒以内' --correction-script examples/dialogue-unanswered.json --headless
```

時刻は探索開始からのシミュレーション秒で、モデル待ち中に時刻が来た入力は、処理可能になってから順に読む。
モデル処理中の計画を途中で差し替えるものではない。最新の質問は標準出力の `QUESTION:` とJSONログに残る。

## 実験中の失敗と修正

最初の確認対話試行では、質問・回答・青の取消しまでは解釈できたが、緑の再確認で停止した。
92.2秒の位置は過去の観測位置から約9 cm離れ、緑に当たるレイは1本だった。
既存の15 cmの到着判定が早すぎて、2本以上という観測条件を満たす前に「見えない」としていた。

観測位置の近くでは格子中心ではなく記録した実位置へ近づき、4 cm以内で再確認失敗を判定するよう修正した。
観測条件の2本は緩めず、新たな観測が得られた場合だけ完了する。回帰テストも追加した。
失敗した生ログは `outputs/dialogue-dev/answered/plan-20261025T143636150506Z.json` に保持する。
実行位置へ戻っても対象が見えない場合は引き続き失敗になる。同色1個・静的環境の前提は変えていない。
