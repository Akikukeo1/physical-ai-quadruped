# 観測履歴比較の追加12配置

初回4配置では訂正の機会が1配置だけだったため、別の12配置（801–812）を追加する。
配置を調べる前に [correction-evaluation-expanded.json](correction-evaluation-expanded.json) を確定した。
同じ4組の言い回しを順番に3回使い、各配置で履歴あり／現在の観測のみを比較する。
初期計画、発火条件、2件目の入力タイミング、比較対象、成功条件は初回と同一。
計画生成・地図・センサー・歩行制御のソースも初回から変更していない。

```bash
.venv-wsl/bin/python scripts/evaluate_corrections.py \
  --protocol docs/correction-evaluation-expanded.json \
  --out-dir outputs/correction-evaluation-v2
```

実行前に仕様と全実行ソースをコミットし、新しい出力先に指紋を保存する。
非発火の配置も置き換えず、全24試行を記録する。インフラ障害の場合は途中結果を保存して停止する。
同じ仕様・ソースでコマンドを再実行すると、完了済みの試行をスキップし、
インフラ障害の再試行を別ファイルへ保存する。プロセスが停止したことと外部条件の変化を確認してから再開する。

追加の理由は初回の機会出現数を見て決めたため、独立した確認実験として初回と無条件に合算しない。
同じ環境生成手続きの中での追加検証であり、カメラ、SLAM、動的対象、複数同色対象、実機は評価しない。
対象色を明示した2件の訂正を扱い、短い回答で色の質問を解決する対話は今回の比較に含めない。
LLMの観測履歴だけを削る比較なので、任意の別手法に対する優位性を示すものでもない。

初回の記録と仕様は変更しない。[初回結果](CORRECTION_EVALUATION.md)を再現する評価スクリプトは `ca0dbd5` の版。
今回 `--protocol` を追加した評価スクリプトは指紋が異なるため、初回の出力先へ混ぜる再開は拒否される。

## 結果

2026-10-26、`9c04257` で仕様・スクリプトを固定した後、Ubuntu 24.04 / WSL2で全24試行を完了した。
途中のソース変更・配置の差し替え・モデル設定の変更はない。インフラ障害はなく、再試行もない。
初回から実行ソース11ファイルの指紋が変わっていないことも確認した。

806の最初の入力は両条件とも43.0秒。LLMへ渡した入力は観測記録以外が完全に一致した。
履歴ありは52.2秒に再確認を追加し、64.4秒に青を明示的に取り消した。
`obs-42-green` を参照して68.4秒に緑を新たに観測し、84.8秒で帰還した（帰還誤差0.1158 m）。
現在の観測のみの条件は緑の観測記録を求める質問を2回返し、
148.4秒で未達成の青を残して帰還した（誤差0.1001 m）。緑の再確認と青の取消しは未達成だった。
どちらも待機中の速度指令はゼロで、元の締切・出発地点を保持した。
全24試行の記録したトレースに接触・転倒・非有限値はなかった。

非発火の11配置も生ログを保持する。8配置では緑を観測するより前に青を発見した。
残る3配置（804・807・809）は緑を先に観測したが、緑が見えている間に青を発見した。
「青を先に発見した」だけで非発火を説明するのは不正確だった。
過去の観測だけを使わなければならない場面を、通常の探索中に待つ方式では機会が少ない。

凍結指紋、全24生ログのSHA-256、全指標の再採点、配置806の入力の一致を検証した。
仕様・環境・全件の指標・機会の出現理由・モデル入力と生返答は
[correction-evaluation-expanded-validation.json](correction-evaluation-expanded-validation.json) に保存した。
Windowsの67テストは成功（物理9件スキップ）。追加の仕様選択・凍結拒否を含む4テストはWSLでも成功。
静的検査も成功。物理単体テスト全体の再実行は行わず、凍結した実行ソースを24回実MuJoCoで動かした。

## 解釈と次の比較

別配置・別の言い回しでも、履歴を使うことで再確認と取消しを実行できた。
ただし、今回も実際に比較できたのは1組だけであり、汎化成功率や統計的な優位性は主張しない。
この比較は、過去の参照先を渡すことの効果を調べている。LLMそのものの独自性や他手法への優位性を示すものではない。

次は対象色の役割を入れ替える条件と、現在も対象が見えている対照条件を事前指定する。
前者は色の向きによる偏りを調べ、後者は現在の観測だけの構成でも実行可能な場面で動くかを調べる。
今回の結果を見て選んだ配置を再利用する場合は開発実験と明記し、新たな未使用配置の評価と分ける。
