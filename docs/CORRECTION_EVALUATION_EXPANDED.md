# 観測履歴比較の追加12配置

初回4配置では訂正の機会が1配置だけだったため、別の12配置（801–812）を追加する。
配置を調べる前に [correction-evaluation-expanded.json](correction-evaluation-expanded.json) を確定した。
同じ4組の言い回しを順番に3回使い、各配置で履歴あり／現在の観測のみを比較する。
初期計画、発火条件、2件目の入力タイミング、比較対象、成功条件は初回と同一。
計画生成・地図・センサー・歩行制御のソースも初回から変更していない。

```bash
.venv-wsl/bin/python scripts/evaluate_corrections.py \
  --protocol docs/correction-evaluation-expanded.json \
  --out-dir outputs/correction-evaluation-v2
```

実行前に仕様と全実行ソースをコミットし、新しい出力先に指紋を保存する。
非発火の配置も置き換えず、全24試行を記録する。インフラ障害の場合は途中結果を保存して停止する。
同じ仕様・ソースでコマンドを再実行すると、完了済みの試行をスキップし、
インフラ障害の再試行を別ファイルへ保存する。プロセスが停止したことと外部条件の変化を確認してから再開する。

追加の理由は初回の機会出現数を見て決めたため、独立した確認実験として初回と無条件に合算しない。
同じ環境生成手続きの中での追加検証であり、カメラ、SLAM、動的対象、複数同色対象、実機は評価しない。
対象色を明示した2件の訂正を扱い、短い回答で色の質問を解決する対話は今回の比較に含めない。
LLMの観測履歴だけを削る比較なので、任意の別手法に対する優位性を示すものでもない。

初回の記録と仕様は変更しない。[初回結果](CORRECTION_EVALUATION.md)を再現する評価スクリプトは `ca0dbd5` の版。
今回 `--protocol` を追加した評価スクリプトは指紋が異なるため、初回の出力先へ混ぜる再開は拒否される。
