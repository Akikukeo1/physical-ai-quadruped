# 通路封鎖後の再計画（2026-10-24）

作業前チェックポイントは `b080138` です。
移動してきた障害物で北側の通路が塞がれたときに、Go2を静止させ、
更新後の地図で経路を選び直して青→緑の順に到達する処理を追加しました。

## 実装と観測の範囲

観測はMuJoCoから取得する現在位置と障害物の位置です。画像認識ではありません。
オレンジの箱はmocap bodyとして、開始4秒から6秒までの間にy=3.0からy=1.05へ移動します。
箱の軌跡は環境側のスクリプトです。Go2の位置を書き換えて動かしてはいません。
ロボットは従来と同じMoE方策・関節トルク・接地によって移動します。

残りの全経路を0.2秒ごとに現在の地図で検査します。封鎖を検出したら速度ゼロを指令し、
並進速度0.03 m/s未満・角速度0.05 rad/s未満になったことを確認して再計画を要求します。
Codexへ渡すのはその時点の位置・地図・未訪問の目的地です。将来の箱の軌跡は渡しません。
今回のスクリプトでは、再計画を要求する時点で箱の移動は終了しています。

再計画でも最大8地点、全障害物への安全余裕、未訪問地点の順序を検証します。
訪問済みの目的地の再追加、目的地の省略・入れ替え、不正な経路は拒否します。
再計画は最大2回、Codex応答待ちは各60秒までです。失敗時に別方式で穴埋めはしません。
移動90秒の予算は再計画でもリセットせず、静止待ちの物理時間も予算に含めます。
開始前1秒と最終停止2秒は移動予算とは別です。

**Codexの応答待ち中はシミュレーション時間が進みません。**
計画待ちの実時間をログへ保存しますが、録画はシミュレーション時間で進むため、
ネットワーク待ちの時間は動画に含まれません。実時間で動く環境や実機への対応は未検証です。

## 比較結果

Python 3.12.12、MuJoCo 3.3.7、ONNX Runtime 1.23.2、WSL2 Ubuntu 24.04で、
同じ初期経路 `north_gate → blue → green` と同じ障害物の移動を使用しました。
各方式1回の確認であり、統計的な性能評価ではありません。

| 封鎖後の方式 | 結果 | シミュレーション時間※ | 最終位置誤差 | 再計画の実時間 |
| --- | --- | --- | --- | --- |
| 停止のみ | 封鎖を検出して停止、未到達 | 6.4秒 | — | — |
| ルールによる最短経路 | 青→緑に到達 | 58.6秒 | 8.6 cm | 約0.000085秒 |
| 実Codexによる再計画 | 青→緑に到達 | 58.6秒 | 8.6 cm | 約15.9秒 |

※開始前の姿勢安定化1秒を除き、最終停止2秒を含みます。

ルール方式とCodex方式は、ともに `south_gate → south_exit → blue → green` を選びました。
3方式すべて接触はなく、到達した2方式の10 Hzログでの最小クリアランスは約0.167 mでした。
クリアランスは箱とロボット中心の距離から仮定半径0.45 mを引いた値です。
実際の各リンクからの最短距離そのものではありません。

**この単純な地図では、Codexの幾何経路探索の優位性は示せていません。**
更新した観測に応じて自然言語の計画を変更し、検証済みの同じ制御口へ渡せることを確認した段階です。
ルール方式は小さな可視グラフ上の最短経路探索で、Codexと同じ観測・目的地・安全検査を使います。

比較ログの抜粋は [replanning-validation.json](replanning-validation.json)、詳細ログは
ローカルの `outputs/replanning-comparison/` に保存しています。

```bash
bash scripts/demo.sh --task replanning --planner sample --replanner stop --headless
bash scripts/demo.sh --task replanning --planner sample --replanner rules --headless
bash scripts/demo.sh --task replanning --planner sample --replanner codex --headless
```

初期計画もCodexに作らせた一連の動作も実行し、封鎖検出から静止、南回りへの変更、
青・緑への到達まで録画しました。動画と対応ログは `outputs/replanning-codex.mp4` と `outputs/plan-*.json` です。
対応する実行の情報は上記JSONの `recorded_demo` に記録しています。

## 既知の制限

障害物の動きと地図は今回の1場面に限定しています。シミュレータの正確な位置を使用し、
認識誤差や自己位置推定の誤差は評価していません。判断中に物理時間を止めるため、
連続して変化する環境や実機への安全性・実時間性能を主張できる結果ではありません。
目的地に達したかは指定された順序と位置で判定し、映像の意味理解による判定は行いません。

mocap bodyと位置更新は [MuJoCo 3.3.7の仕様](https://mujoco.readthedocs.io/en/3.3.7/XMLreference.html#body-mocap)に従っています。
