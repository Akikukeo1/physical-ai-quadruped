# 観測履歴を使う訂正の配置比較

方針変更後の既知のseed 305での成功から、同じ手続きで作る別配置への適用範囲を調べる。
実行前の仕様は [correction-evaluation.json](correction-evaluation.json)。
使用する配置・言い換え・順序・採点・中断規則を、最初の配置を調べる前にコミットする。

4配置 × 履歴あり／現在の観測のみの2条件、合計8試行。
後者でも地図、会話、タスク、帰還条件、実行器は同じで、LLMへ渡す過去の観測だけを減らす。
実行中の再確認タスクの参照先は残す。LLMが新たに参照先を選ぶ際の履歴の有無を比較するもので、
地図や観測履歴を実行器から削除したロボット同士の比較ではない。

初期計画は共通の青探索・180秒・帰還に固定し、訂正解釈だけに実Codex CLIを使う。
センサー履歴から「緑を見たが現在は見えておらず、青はまだ見ていない」機会を検出する。
その機会が90秒までに発生しなかった試行も記録し、別の配置へ差し替えない。
1件目を解釈した2シミュレーション秒後に、受理・質問のどちらでも同じ2件目を送る。
任意の質問へ適応的に答える人の対話成功率を測る実験ではない。

```bash
.venv-wsl/bin/python scripts/evaluate_corrections.py
```

実行前に `outputs/correction-evaluation-v1/frozen-inputs.json` へソース・仕様・依存バージョンを保存する。
各試行の観測、LLMへ渡した入力、生のJSON応答、速度指令、物理トレースを別ファイルに保存する。
結果は `evaluation.json` に逐次追記。429等の応答取得失敗でバッチを停止する。
プロセスが停止したことを確認し、外部条件が変わった後に同じコマンドで再開できる。
完了済み試行はスキップし、インフラ失敗の再試行は別ファイルで保存して前の失敗を残す。
凍結した内容が変わっていれば再開を拒否する。

安全に帰還しただけでは訂正後の任務成功に数えない。新しい緑の観測、青の明示的な取消し、
帰還完了、未達成タスクなし、元の期限・出発点の保持、待機中のゼロ速度指令まで要求する。
非発火・言語失敗・物理失敗・インフラ失敗を分けて報告する。
インフラ失敗後の停止位置を、モデルの言語能力や帰還能力の成績には使わない。

4配置・各1回に限るため、結果から一般的な汎化性能や統計的な優位性は主張しない。
同じ配置の結果を見て改良した場合、その配置は開発例へ移し、次の評価配置を新たに事前指定する。
