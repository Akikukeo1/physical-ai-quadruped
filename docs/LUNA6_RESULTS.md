# Luna 6 / xhigh の最初の言語実験

2026-10-26、`b9229bb` で固定した `gpt-6-luna` / `xhigh` を使用した。
呼び出しで指定した設定であり、サーバー側の実モデル名を別途取得した記録はない。
過去のモデル未指定の結果は変更しない。

```bash
.venv-wsl/bin/python scripts/probe_corrections.py \
  outputs/task-revision-dev/reobserve/plan-20261024T201811354659Z.json \
  --out-dir outputs/language-probes-luna6-xhigh
```

保存済みの同じ観測を使い、8入力 × 履歴あり／なしの16条件を予定した。
このバッチは言語解釈だけで、ロボットを動かした試行ではない。
事前の期待値は既存スクリプトのまま。結果に合わせて変更していない。
入力・応答・検証結果・元ログのSHA-256は [luna6-language-validation.json](luna6-language-validation.json)。

| 履歴ありの入力 | 応答 | 事前期待との一致 |
| --- | --- | --- |
| 青をやめて緑へ変更 | 青を取消し、緑を探索して帰還 | 一致 |
| 青を保持して緑を先に追加 | 緑 → 青 → 帰還 | 一致 |
| 緑をもう一度確認して青を再開 | 過去の緑の観測2件のどちらかを質問 | 不一致 |
| さっき見えた対象をもう一度確認 | 緑を再確認 → 青 → 帰還 | 一致 |
| 青を取消して今すぐ帰還 | 青を取消して帰還 | 一致 |
| あっちを先にして | HTTP 429、応答なし | 採点対象外 |

応答を得た5件中4件が期待したタスク列と一致した。1件は安全な確認質問だったが、
再確認へ進むという期待を満たさなかった。スキーマや実行側の検証で弾かれた応答ではない。
同じ色の過去の観測が複数ある場合に、どの記録を使うかという余分な曖昧さが残っている。
この結果を受けてプロンプトや採点基準を変更する場合、同じ条件での再試行は開発実験と明記する。

6件目で429となり、その時点で停止・保存した。残り10条件は未実施。
これは4/16というモデル正解率を意味しない。履歴なし条件は未実施であり、履歴の効果も比較できない。
過去の16/16はモデル・確認方針が異なるため、今回の4/5とモデル間の優劣比較には使えない。

## 次に確かめること

2. 開発条件で、対象が1個でも観測が複数あるときの選択方針を明文化する。既存の履歴を消して解決しない。
3. 方針を固定してから、新しい配置・言い回しの比較条件を事前に決めて実行する。
   訂正適用・元の義務の保持・新規観測・期限内帰還を別々に採点し、
   確認回数・停止時間・物理失敗・インフラ失敗も分ける。
