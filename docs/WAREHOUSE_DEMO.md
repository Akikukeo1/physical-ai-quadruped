# 設備調査の実演表示と同期録画

既存の `scripts/investigate.py` に `--demo` と `--record-dir` を追加した。
`--demo` は設備の3D表示、`--record-dir` は3D表示と2視点の同時録画を有効にする。
新しい歩行方策・物理シミュレータ・動画編集ツール・依存ライブラリは追加していない。

## 収録

既存のWSLセットアップが完了した環境で、リポジトリルートから実行する。

```bash
MUJOCO_GL=egl .venv-wsl/bin/python scripts/investigate.py \
  --scene A --probe --development-fault airflow_fault --headless \
  --record-dir outputs/warehouse-demo
```

`--record-dir` の下にUTC時刻のフォルダを作る。既存の収録は上書きしない。
ビューアで動かす場合は `--headless` を外す。録画せず3D表示だけを使う場合は `--demo`。
`--record-dir` 指定時の実行ログは収録フォルダ内の `execution.json` に保存する。
未指定時の既存CLI・保存先は維持している。

| ファイル | 内容 |
| --- | --- |
| `overview.mp4` | 全景。設備の位置、Go2の移動・帰還を確認 |
| `follow.mp4` | Go2追従。計測位置への移動、プローブの展開・格納を確認 |
| `execution.json` | 実Codexへの入力、判断、仮説、観測、計測幾何、行動、物理トレース、診断・帰還の評価 |
| `frames.json` | 共通フレーム番号、動画内秒、正確なシミュレーション秒、実際に表示したHUD状態 |
| `timeline.json` | 判断要求・結果、点検、計測、報告、帰還開始と、その近傍フレームへの索引 |
| `manifest.json` | FPS・解像度・カメラ設定・各ファイル名・対応誤差 |

両MP4は720×560・25fps。720×480のMuJoCo描画に、上部80pxのHUD専用領域を加える。
各20物理ステップ（0.04秒）で同じ状態を2つの視点から描く。
初期姿勢の安定化も録画に含み、動画の0秒を任務開始時刻と仮定しない。
対応関係は `frames.json` を使う。フレーム0はシミュレーション0.04秒。
物理のリプレイや任意に動かしたモデルではなく、実際の制御・物理実行中に描画した映像。
速度変更、カット、音声、BGM、演出は加えていない。

画面上のHUDも収録時に生成する。現在の行動、LLMが返した仮説状態、最後に受理した観測、
最終結論、シミュレーション秒を表示する。文字は英語の固定ラベルと実際の構造化値を使用する。
日本語の判断理由・測定目的・不確実性・報告全文は `execution.json` に残す。

HUDの `INITIALIZING` は初期安定化、`LLM_WAIT` は応答・計画適用待ち、`INSPECT` は設備点検、
`MEASURE` は計測の移動・位置合わせ・展開・格納、`RETURN_HOME` は帰還。
仮説の `possible` は未確定、`supported` は観測による支持、`ruled_out` は今回の観測範囲で否定された候補。
絶対的な故障除外を保証せず、報告の不確実性と併せて読む。

`timeline.json` のイベント時刻は観測取得・判断取得等の正確な時刻を保持し、最も近い物理フレームを示す。
HUDへの反映は、静止確認やプローブ格納後の観測受理を経て次の描画で行うため、取得時刻と同一ではない。
`frames.json` の `status` がそのフレームで表示した内容の正本。
監査後の `qa.json` にある `hud_changes` は、値・仮説・結論が実際に画面へ現れたフレームを示す。

## 設備とカメラ

- 冷却機：青い縦型筐体、通風格子、ファン形状、吹出口と2つの計測領域。
- 電源盤：灰色の盤、表示器、黄色の注意表示、3つの遮断器。
- 扉：枠、両面の窓と取っ手、扉板。模擬世界の扉開放状態は表示にも反映する。
- オレンジのサービス地点は1=電源盤、2=冷却機、3=扉。黄色の円は出発地点。

全景は距離8.4m・方位−35度・仰角−58度。追従は距離1.9m・方位−35度・仰角−28度。
設備の正面と計測中のGo2が見え、全景では電源盤が画面外へ出ないよう、実描画を比較して調整した。

設備形状は表示専用の `group=4, contype=0, conaffinity=0`。
既存の衝突形状、距離センサー、模擬設備点検、計測場は変更しない。
見た目の設備表面すべてが衝突判定と一致するという意味ではない。
Go2の質量・慣性・関節制御を変更せず、表示有無の同じ移動指令で `qpos` が1e-10以内で一致し、
距離スキャンも同一になることを物理テストで確認した。
設備表示とHUDはLLMへの新しい観測ではなく、カメラ認識は実装していない。
プローブは引き続き運動学モデル、空気温度・風速は幾何条件付きの簡易解析場。

## 録画の監査

```bash
.venv-wsl/bin/python scripts/verify_demo_recording.py outputs/warehouse-demo/<収録フォルダ>
PAI_SIM_TEST=1 .venv-wsl/bin/python -m unittest discover -s tests -v
```

監査スクリプトは両動画を最初から最後まで復号する。
解像度・FPS・全フレーム数、シミュレーション時間の0.04秒刻み、イベントとの対応、HUDの観測・仮説が
実行ログに存在することを検査する。既存の任務監査も呼び、計測条件・証拠付き診断・安全性・期限内帰還を確認する。
確認用の静止画を `qa/`、集計・動画SHA-256・HUD変化の索引を `qa.json` に保存する。
これらの静止画は動画からの確認用抽出で、映像自体を編集するものではない。

過去の成功ログ、プローブ評価、Map Bの凍結評価は変更していない。
今回の収録は開発用Map Aでの実演検証で、新しい未見環境評価や汎化性能の証明ではない。

## 実収録の結果（2026-11-02 JST）

提出用の未編集映像は `outputs/warehouse-demo-ready/20261101T201004013790Z/` に保存した。
フォルダ名はUTC。全景・追従とも62.00秒・1,550フレーム、720×560・25fps。
両動画の全フレームを復号し、欠落・フレーム数の不一致がないことを確認した。
イベントと近傍物理フレームの時刻差はこの試行では0秒。一般の量子化誤差上限は20ms。

実Codexが冷却機点検から温度測定を選び、−8.417°Cを受けて風速測定を選んだ。
風速0.044m/sから送風不足を支持し、未点検の扉・複合故障・ファン故障か風路閉塞かの不確実性を報告して帰還した。
任務は61.0シミュレーション秒、初期安定化を含む映像は62.0秒。帰還誤差13.4cmで15cm以内、
360秒の期限内、転倒・接触なし。仮説・表示値と実行ログの対応も監査した。
