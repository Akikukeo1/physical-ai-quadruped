# 制約を伴う訂正対話の言語試行

これは実行器に接続しない開発用の実験。自然言語を構造化し、保持と解除を検証する部分だけを試す。
実ロボット・MuJoCoで領域制約に従って動いた証拠にはならない。

制約は「過去に観測したときのロボット位置を中心とする円」を表す。
LLMは観測IDと0.2–1.5 mの半径、制約ID、ユーザー発言の引用を返す。隠れた物体座標やコードは返さない。
既存のタスク列とともに有効な制約を保持し、解除時は制約IDとユーザー発言の引用を返す。
同じIDの意味変更や、解除済みIDの再利用は拒否する。確認質問中にはタスクや制約を変更しない。
引用の一致だけでは、その文章が本当に追加・解除を意味することまでは証明できない。

事前に次の3入力を固定し、以前の開発試行で得た観測状態を使う。成功した出力だけを次の入力に引き継ぐ。

1. 緑を見た地点の半径0.5 m以内を避け、青の探索を続ける。→ 観測に根拠のある制約を追加し、青と帰還を保持。
2. その緑を見た地点へ戻り、もう一度確認する。→ 立入禁止と明示的な入域要求が衝突するため、状態を維持して質問。
3. 立入禁止を解除し、その地点で緑を再確認する。→ 該当制約を引用付きで解除し、緑の再確認・青・帰還を残す。

2の衝突は「その禁止領域内の地点へ戻る」という明示的な指示についてである。
領域外から対象が見える可能性はあり、一般的な再観測が不可能だと主張しない。
誤りや接続障害があれば途中で止め、残りは未実施として記録する。

```bash
.venv-wsl/bin/python scripts/probe_constraint_revision.py \

```

実験では `gpt-6-luna` / `xhigh` を要求し、観測状態のSHA-256・モデルへの入力・生JSON・検証結果を保存する。
この1例は開発用であり、未見の指示や配置に対する性能ではない。
実行器への接続には、制約の保持と解除だけでなく、適用時の安全な現在地・帰還経路の確認、
探索・帰還時の制約付き経路、走行中の監視が必要。既存の探索経路には接続していない。
