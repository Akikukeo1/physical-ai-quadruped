# 探索エージェントの試作

## Windowsから操作する

WSL上の実行環境とCodex CLIの準備後、リポジトリのPowerShellから以下を実行する。

```powershell
.\.venv\Scripts\pythonw.exe scripts\interactive.py
```

最初のメッセージを入力して「開始」を押す。会話だけの場合は探索指示を待ち、青または緑の探索を指示するとMuJoCoが別ウィンドウで開く。下の欄から会話や追加指示、確認への回答を送れる。送信後は応答が表示されてから次のメッセージを送る。エリアJSONは開始前に選べる。試行のログは `outputs/interactive/` に保存される。探索開始前と開始後はそれぞれ最大12メッセージで、開始後は初期指示も1件に数える。モデル応答の待ち時間や元の制限時間により、指示を完遂できない場合がある。

操作画面での通常の会話は計画を変えず、返答を表示する。探索中は返答を待つ間も元の制限時間が進む。探索を開始する判断もLLMによるため、意図を誤解する可能性がある。既存の `--agent` のコマンドライン動作は変わらない。

`--agent` は、Codex CLI に探索中の高水準判断を繰り返し依頼する開発用モード。
従来の探索・訂正モードは変更しない。エリアを使わずに実行することもできる。

```bash
MUJOCO_GL=egl bash scripts/demo.sh --task search --planner codex --headless --seed 305 \
  --agent --field-areas examples/field-areas.json --correction-script examples/agent-combined.json \
  --prompt '青を探し、見つからなくても出発地点へ戻って。全体240秒以内。' \
  --out-dir outputs/agent-example --video outputs/agent-example.mp4
```

初期指示はまず単一対象・期限・帰還の基本計画に変換し、初回のセンサー観測後にもう一度LLMへ渡す。
以後の人の訂正は、タスク列とエリアの通行可否を同じJSONでまとめて変更する。
過去の観測ID、残タスク、帰還義務と期限を保持し、曖昧な場合は変更せず確認を求める。
同時に新しい制約を適用する場合は、現在地と観測済み地図での帰還経路、再確認地点の到達可能性を検査する。

次の探索地点が必要になると、実行器が観測済みの安全な格子から最大4つの候補を生成する。
LLMは観測履歴、残タスク、エリア条件、以前の選択、候補の経路距離と情報量、
直前の地点に到達したか・到達不能になったかを受け取り、候補IDを1つ選ぶ。
候補以外の座標やコードは受け付けない。選択が古くなった場合は観測済み地図で再検査する。
候補の生成、障害物・禁止領域の検査、歩行と関節制御は既存の実行器が担当する。
候補がなくなった場合や帰還余裕を使い切った場合は、実行器が未発見として帰還する。
実行器の異常や不正なLLM出力に対して自律的に回復する機能はまだない。

モデルの応答中はゼロ速度を指令しつつ物理を進め、元の期限と帰還余裕を維持する。
選択待ち中の人の訂正は優先され、古い選択は採用しない。選択理由と候補・入力状態は `decisions` に記録する。
複合訂正の提案と結果は `corrections` に保存する。遅延や応答失敗は実運用上の制約になる。
`corrections` は最大12件で、エージェントモードでは初期指示もこのうち1件として扱う。

## 最初に分かっている情報

初期のCodex計画にはユーザーの指示を渡す。正解地図、障害物、対象位置、配置seedは渡さない。
探索実行器は、360度の距離・表面色を最大1.8mまで調べる理想化センサーを使い、観測した領域だけを地図にする。
ただしロボットの位置・姿勢にはMuJoCoの真値を使用する。カメラ画像でもSLAMでもない。
ユーザーが事前に描いたエリアはその座標が既知で、LLMにも渡る。エリアは障害物や対象の位置を示さない。
観測対象は青と緑で、初期指示・訂正・行動の種類にはスキーマ上の制限がある。
LLMは全指示を完遂できるわけではなく、引用検査だけで意味の正しさも保証できない。

## 開発中の実行記録

開発途中の実Codex CLI・MuJoCoの1試行では、初期指示を受理し、未知領域の探索候補を5回選んだ。
「エリア2を避け、過去の緑を再確認してから青を続ける」という途中の複合指示では、
提案後の現在地・安全経路を検査できず、実行器が確認質問に切り替えた。
変更は適用されず、回答がないまま帰還余裕に達したため、青を未達成として206.2秒で帰還した。
帰還誤差は0.116m。複合任務の成功ではない。ログは `outputs/agent-dev/` に保存している。

別の開発途中の試行では「エリア2は避け、先に緑を探し、青も続ける」という指示を受理し、
エリア2の禁止を維持して緑を探索、過去に観測した青を確認し、166.6秒で帰還した。
未達成タスクはなく、帰還誤差は0.111m。探索候補の選択は9回だった。
エリア2を禁止した後の0.1秒間隔の記録で、ロボット中心とエリア境界との最短距離は0.290m。
接触は記録されていない。この試行は最終版に観測要約を追加する前の開発ケースであり、汎化評価ではない。
ログと実録画は `outputs/agent-combined-dev/` と `outputs/agent-combined-dev.mp4` に保存している。

その後、観測要約とログ記録を追加した120秒予算の実Codex CLI・MuJoCo試行では、初期指示の解釈は受理されたが、
「エリア2を避けて、緑を先に探す」という次の指示の解釈が30秒でタイムアウトし、停止した。
タスク完了や言語解釈の成功とは数えない。ログは `outputs/agent-final-smoke/` に保存している。
タイムアウトはモデルの意味理解の失敗とは区別する。

最終実装の240秒予算の実Codex CLI・MuJoCo試行では、同じ複合指示を受理し、エリア2を禁止した上で
「緑 → 青 → 帰還」のタスク列を保持した。LLMは探索候補を8回選んだ。
青は68.6秒に観測したが、先に緑を探す指示を保持していたため、青のタスクは完了しなかった。
緑を発見できないまま帰還余裕に達し、緑・青を未達成として225.0秒で帰還した。帰還誤差は0.092m。
禁止後の0.1秒間隔のトレースにエリア2への侵入や障害物接触はなく、境界までの最短距離は0.792mだった。
探索候補の選択にかかった実時間の合計は約90.1秒。この1例は複合任務の成功ではなく、汎化性能も示さない。
ログは `outputs/agent-final-run/` に保存している。
